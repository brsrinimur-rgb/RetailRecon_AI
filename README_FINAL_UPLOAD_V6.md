RetailRecon AI V6 - Exception Correction Maker-Checker

Correction workflow:
1. Maker/Admin/Finance user submits corrected Auth Code with mandatory reason/evidence.
2. Request is stored PENDING APPROVAL with original Auth, Store, Receipt and D365 Row.
3. Finance Checker / Finance Manager / Admin may approve or reject.
4. The submitter cannot approve or reject their own request.
5. Approved correction is applied to the current reconciliation immediately.
6. Approved corrections are also reapplied automatically on future reconciliation reruns.
7. Original Auth Code is retained in audit columns.
8. Audit trail records maker, approver, submission time, approval time and comments.

All prior Store 614, TABBY, TAMARA, TAP and Cash controls remain included.
